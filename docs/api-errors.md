# Ошибки API

Общие обработчики подключены ко всем маршрутам в `src/main.py`.
Ожидаемые ошибки возвращают JSON с полем `detail`; ошибки валидации
FastAPI возвращают в этом поле список с указанием ошибочных полей.
Внутренние сообщения БД и traceback не передаются клиенту.

| Код | Ситуация |
| --- | --- |
| 401 | Неверные данные входа, отсутствующий/неверный/просроченный токен, удалённый пользователь в `/auth/me` |
| 404 | Отсутствующий отель, номер или удобство, в том числе ссылки на них при создании/изменении номера |
| 409 | Дубликат, конфликт внешнего ключа, отсутствие свободных номеров |
| 413 | Изображение больше 10 МБ или 25 миллионов пикселей |
| 415 | Формат изображения отличается от JPEG, PNG и WEBP |
| 422 | Неверные поля/даты, пустой PATCH, недопустимый null, повреждённое/пустое изображение |
| 500 | Непредвиденная внутренняя ошибка; причина записывается в лог |
| 503 | Ошибка соединения/таймаут БД, Redis или брокера, недоступное хранилище изображений |

## Изменения запросов

- Создание и PUT номера требуют `title`, `price >= 0`, `quantity >= 1`.
  PUT заменяет данные: пропущенное описание очищается, пропущенный список удобств становится пустым.
- PATCH требует хотя бы одно известное поле. Явный `null` разрешён только для описания номера.
- ID объектов должны быть положительными. Названия не могут быть пустыми или состоять из пробелов.
- Дата выезда должна быть строго позже даты заезда; занятый номер возвращает 409.
- Имена загружаемых файлов генерируются сервером. Содержимое проверяется до запуска фоновой задачи.

Ошибка фоновой задачи после отправки ответа записывается в лог; уже отправленный HTTP-ответ
не меняется. Для получения статуса обработки потребуется отдельный механизм задач.
Обработчики HTTP не распространяются на ошибки запуска приложения (lifespan).

## Проверка без PostgreSQL и Redis

```sh
venv/bin/python -m unittest tests.unit_test.test_exception_handlers tests.unit_test.test_api_errors tests.unit_test.test_db_errors
```

Эти тесты проверяют HTTP-ответы с подменой репозиториев, обработчики ошибок и освобождение
сессий. Они не заменяют интеграционные проверки с настоящими PostgreSQL и Redis.
